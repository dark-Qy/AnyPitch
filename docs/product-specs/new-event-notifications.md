# 新活动通知调研（2026-10-22）

## 目标

教练发布新的训练、友谊赛或野球活动后，已主动授权的成员收到一条微信服务通知，点击进入对应活动详情。仅讨论新建活动，不把编辑、取消和报名状态变化混入第一版。

## 平台前提

- 小程序端必须由成员主动点击按钮后调用 `wx.requestSubscribeMessage`。弹窗结果为 `accept` 才能记录可发送额度；静默勾选或在后台自动申请不可行。
- 普通一次性订阅是一次授权对应一条消息；不能把“订阅新活动”描述为永久开启。可在「我的」提供“接收下一条新活动提醒”，并显示剩余可用次数，发送成功后扣减。重复授权可积累额度，具体上限与模板支持以微信后台和真机结果为准。
- 需要在微信公众平台「订阅消息」选用与球队新活动相符的模板，取得模板 ID 和字段定义。长期订阅模板是否向当前小程序类目开放，必须在该 AppID 后台核实；在核实前按一次性订阅设计。
- 服务端使用已有微信成员 open_id、服务端 AppSecret 取得 access token，调用订阅消息发送接口。AppSecret 不进入小程序包。消息中的 `page` 指向已发布版本存在的活动详情路径。

## 最小实现还需要的能力

1. 成员端：明确的订阅按钮、微信弹窗结果与拒绝／失败反馈；展示“下一条通知”而非永久推送承诺。
2. 服务端：按成员和模板保存可用授权次数；教练创建活动成功后生成待发送任务；每个「活动 × 成员」只发送一次，避免重复创建或重试导致多发。
3. 投递：异步发送、记录微信错误码和结果；失败时区分可重试故障与授权失效，不能把未发送的通知显示成成功。成员停用或离队后停止发送。
4. 运营验证：先确认模板与类目可用，再用真机授权、创建测试活动、收到通知、点开活动详情走通全链路。开发者工具模拟不等于真机收到消息。

## 决策点与当前状态

默认建议只提醒**新活动**，不限训练类型；一次性授权用于**下一条**活动通知。若微信后台没有合适模板，需要先申请模板并等待审核。当前仓库没有订阅消息模板 ID、授权存储或投递任务，本调研没有启用推送。

参考：[腾讯云小程序订阅消息实践](https://cloud.tencent.com/document/product/1301/103770)、[微信小程序订阅 API](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)、[微信订阅消息发送 API](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/mp-message-management/subscribe-message/sendMessage.html)。腾讯云文档说明了一次性额度、用户点击和模板配置；微信文档链接需在开发时用当前后台再次核实。
