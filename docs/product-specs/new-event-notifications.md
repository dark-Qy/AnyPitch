# 新活动订阅提醒（2026-10-23）

## 目标

教练发布新的训练、友谊赛或野球活动后，已主动授权的成员收到一条微信服务通知，点击进入对应活动详情。仅讨论新建活动，不把编辑、取消和报名状态变化混入第一版。

## 平台前提

- 小程序端必须由成员主动点击按钮后调用 `wx.requestSubscribeMessage`。弹窗结果为 `accept` 才能记录可发送额度；静默勾选或在后台自动申请不可行。
- 普通一次性订阅是一次授权对应一条消息；不能把“订阅新活动”描述为永久开启。「我的」提供“订阅下一条活动”，并显示未被新活动占用的授权次数。新建活动时占用一次授权；重复授权可积累额度，具体上限以微信后台和真机结果为准。
- 需要在微信公众平台「订阅消息」选用与球队新活动相符的模板，取得模板 ID 和字段定义。长期订阅模板是否向当前小程序类目开放，必须在该 AppID 后台核实；在核实前按一次性订阅设计。
- 服务端使用已有微信成员 open_id、服务端 AppSecret 取得 access token，调用订阅消息发送接口。AppSecret 不进入小程序包。消息中的 `page` 指向已发布版本存在的活动详情路径。

## 当前实现

1. 成员端：「我的 → 新活动提醒」调用微信订阅弹窗；仅在 `accept` 后保存授权，拒绝和失败会给出反馈。同步失败时复用授权编号重试，避免重复计数。
2. 服务端：按成员保存未占用授权次数；活动插入与待发送任务、授权占用在同一数据库事务内完成。每个「活动 × 成员」最多一个任务。
3. 投递：后台任务发送微信订阅消息，记录发送结果和错误码；停用成员或已取消活动在发送前跳过。发送状态不明时不自动重试，以免重复提醒。
4. 模板：微信后台已加入「新活动发布提醒」，字段为活动名称、开始时间、活动地点和备注；模板 ID 仅配置在服务端，由成员状态接口提供给小程序使用。

## 验证边界

提醒适用于新建的所有活动类型；编辑、取消和报名变更不会发新活动提醒。自动化测试验证授权幂等、活动创建占用和发送字段。微信真机授权、实际送达及点击落地页仍需在开发版上验证。
